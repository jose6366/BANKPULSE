# Estrategia de ramas
Se usa GitHub Flow: `main` siempre debe ser integrable. Cada historia se desarrolla en `feature/<hu>-descripcion`, se abre un Pull Request, otro integrante revisa/comenta y luego se fusiona.

Ejemplo del Sprint 1:
`feature/hu-bp-03-create-payment` -> Pull Request -> revisión -> merge a `main`.
